System Architecture

OPS Coordinator Multi-Agent System

A single external endpoint, POST /analyze, hands a free-text ops request to a Claude-driven coordinator. The coordinator is the only component that reasons about routing — everything under it is a plain Python function that makes one independent call to the same Claude API with its own system prompt.

Python FastAPI Anthropic Claude API — claude-sonnet-5 Tool use / agentic loop

Request Flow

Routing Rules

User request mentions…Agents activated
"ticket analysis", "incident analysis", "log analysis", "root cause", "SLA", "error details", or a ticket ID ServiceNowAgent + SplunkAgent + EmailAgent
Only asks for logs SplunkAgent only
Asks to send / prepare a report EmailAgent (+ whichever agents it needs for content)

Response Shape

{
  "ticket_summary": "...",
  "log_analysis_summary": "...",
  "recommended_fix": "...",
  "email_report": {
    "subject": "...",
    "body": "..."
  }
}

Component Reference

Target Architecture — Real ServiceNow / Splunk / Email Not yet implemented

The code today reads data/dummy_data.py. This is the intended design for swapping those lookups for live systems: each sub-agent keeps its own Claude call, but trades its dummy-data lookup for a call through an MCP client to a dedicated MCP server — ServiceNow and Splunk MCP servers, plus an email-sending MCP server (e.g. Gmail).

Max 6 tool-use turns per request (MAX_TURNS in coordinator.py); a malformed final reply from Claude falls back to a best-effort response instead of a 500.
